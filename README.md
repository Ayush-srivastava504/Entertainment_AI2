# Animegirl4u — AI Entertainment Platform

Next.js (App Router, TypeScript, Tailwind) frontend, deployed on Vercel.
Postgres is the single source of truth for everything the frontend reads —
nothing calls a third-party API (TMDB, AniList, OpenTDB, RSS feeds) at
request time.

```
Scheduled crawlers (GitHub Actions)  →  write rows into Postgres
On-demand AI tools (movie/anime      →  Vercel API route calls an
  recommender, tag generator, etc.)     external AI endpoint directly and
                                         returns the result in the same
                                         request (see lib/ai.ts) — not
                                         configured currently, so these
                                         tool pages show a friendly error
Every page                            →  reads Postgres, nothing else
```

There is no EC2 instance and no daily batch job. Content is generated by
real scheduled crawlers, and the on-demand AI tools (optional) are
answered synchronously by a single request rather than a queued batch
run.

## Adding your own original GIFs (Supabase Storage)

Originally these lived directly in the git repo (`public/original-gifs/`). That's gone now — committing dozens of MB of binary GIF/image files into git makes every future clone/pull/push slower forever, since git never shrinks back down once something's been added to its history. They're served from **Supabase Storage** instead: same "just drop files in" simplicity, no code, no database work, but without bloating the repo.

**One-time setup, in your Supabase dashboard:**
1. Go to **Storage** → **New bucket** → name it exactly `original-gifs` → toggle **Public bucket** ON (this is what lets the site display them without extra auth code).
2. In Vercel, confirm `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY` are set (Project Settings → API in Supabase, same two values from earlier in this build — they may already be in Vercel, just unused until now).

**Every time you want to add GIFs:**
1. Name each file descriptively with dashes, e.g. `shy-wave-hello.gif`. The site turns this into the display title automatically ("Shy Wave Hello").
2. In Supabase → Storage → the `original-gifs` bucket, click **Upload files** and drag your files in.
3. That's it — no redeploy needed. The site re-checks the bucket every 5 minutes, so new uploads appear on the homepage, `/stickers`, and get their own `/gif/original-<filename>` page (with its own AI caption) shortly after upload.

These are prioritized ahead of Tenor/Giphy results in search, since they're your unique content. Re-run `db/schema.sql` once if you haven't already (see below) — it accepts `"original"` as a caption source.

## New: Anime stickers & GIFs

The homepage, `/stickers`, and `/gif/[id]` now pull anime GIFs/stickers live
from the Tenor and Giphy free APIs (not re-hosted — we link their CDN URLs
directly, per both services' terms). Each `/gif/[id]` page also gets a
short, original Gemini-written caption, generated once per GIF and cached
forever in the new `gif_captions` Postgres table — the same `GEMINI_API_KEY`
already used by the offline `ending-explained` generator powers this, just
called at request time instead of by a crawler script.

Required for this feature: `TENOR_API_KEY`, `GIPHY_API_KEY` (new — add to
Vercel env vars), `GEMINI_API_KEY` (already in your env vars). Without the
Tenor/Giphy keys the stickers section just renders empty rather than
erroring. Without `GEMINI_API_KEY` set, GIFs still display and download
fine — only the caption text is skipped.

Not yet done: `/stickers` and `/gif/[id]` aren't in `lib/sitemap.ts` yet
(they're reachable via the homepage and nav either way, so this only
affects how fast they get crawled/indexed) — add them there when you're
ready to prioritize that traffic.

## 1. Run the frontend locally

```bash
npm install
cp .env.example .env.local
# set DATABASE_URL at minimum — see "Set up the backend" below
npm run dev
# → http://localhost:3000
```

Catalog/blog/quiz pages need Postgres populated by the crawlers (step 2) to
show anything. The on-demand AI tools (tag generator, thumbnail rating)
need `HF_SPACE_URL` set (step 3) to return a result.

## 2. Set up the backend (Postgres + crawlers)

1. Create a free Postgres (Neon or Supabase), run `db/schema.sql` against it.
   For an existing database, run `npm run db:migrate:title-requests` to add the homepage request queue without touching existing comments.
2. Put `DATABASE_URL` in Vercel's env vars **and** as a GitHub Actions
   secret (Settings → Secrets and variables → Actions) for the same repo —
   `.github/workflows/sync.yml` runs the crawlers on a schedule using it.
3. Get a free `TMDB_API_READ_ACCESS_TOKEN` and add it as a GitHub secret too.
4. Run `npm run crawl:all:full` once locally (or trigger the workflow
   manually) to do the first full catalog load.

## 3. On-demand AI tools (optional, currently unconfigured)

The tag generator and thumbnail-rating tools (`app/tools/`) call out to
an external AI text-generation endpoint via `lib/ai.ts` /
`app/api/queue/route.ts`. This site runs on Vercel only — there's no EC2
box and no Hugging Face Space behind it right now, so `HF_SPACE_URL` is
unset and those two tool pages simply show a friendly "unavailable"
error. Every other part of the site (catalog, blog, quizzes) is
unaffected.

If you want these tools working again, point `HF_SPACE_URL` at any HTTP
endpoint that accepts `{ prompt, max_tokens, temperature }` and returns
`{ text }`, and set it in Vercel's env vars.

## 4. Deploy the frontend to Vercel

```bash
npm i -g vercel
vercel
```
Add `DATABASE_URL`, `NEXT_PUBLIC_SITE_URL`, and `REVALIDATION_SECRET` in
Project Settings → Environment Variables. (`HF_SPACE_URL`/`HF_TOKEN` are
optional and only needed if you wire up the on-demand AI tools — see
section 3.)

## 5. Attach a custom domain

See **[`DOMAIN_SETUP.md`](./DOMAIN_SETUP.md)** — in short: add the domain
in Vercel, point its DNS at Vercel, then update one environment variable
(`NEXT_PUBLIC_SITE_URL`). Nothing else in the code needs to change.

## 6. Security

See **[`SECURITY.md`](./SECURITY.md)** for what's already locked down
(parameterized queries, security headers, rate limiting, secret handling)
and what to double check before going live.

## 7. Add more on-demand AI tools

Every tool follows the same shape:
1. Add a case to `buildPrompt()` in `lib/prompts.ts`.
2. Add the task name to `VALID_TASKS` in `app/api/queue/route.ts`.
3. Add a page that renders `<ToolShell task="..." buildInput={...} />`.

No new backend, no new model — same AI endpoint, one more prompt.
